# Repository Guidelines

## Область работы и структура

Работайте только внутри `alex/`, если пользователь явно не расширил задачу. Перед изменениями проверяйте текущие YAML и код; не восстанавливайте пользовательские файлы из Git поверх локальных правок.

- `solver_python/` — единственный активный решатель: Python, NumPy, Numba, CPU.
- `solver_python/tests/` — pytest и численные регрессионные проверки.
- `solver_python/sources/` — пользовательские функции источника.
- `solver_python_run/` — простые bash-запуски с параметрами внутри.
- `configs/<name>/` — `<name>.yaml` и `README.md` с постановкой эксперимента.
- `results/<name>/` — все результаты одного эксперимента.
- `legacy/` — прежние C++, GPU, скрипты, курсовая, презентации и архивные результаты. Активный runtime не должен зависеть от архива. Исключение: тест сравнения с архивным C++.

`README.md` — руководство пользователя. Этот `AGENTS.md` — рабочие правила для разработчиков и агентов. Архивные документы описывают прежние версии, а не актуальные требования.

## Конфигурация и запуск

Имя YAML без расширения определяет имя эксперимента: `configs/example/example.yaml` → `results/example/`. Поля `experiment` и `output.root` запрещены. Пути к источнику и файлу стабилизации разрешаются относительно YAML. Геометрия, физика, шаг, число итераций, сохранение и потоки задаются в YAML.

Не добавляйте отдельные скрипты продолжения расчёта. Необязательный блок `resume` в YAML содержит **оба** пути `psi` и `omega` к снимкам ALEXBIN1, относительно YAML. Из каждого файла читается соответствующая компонента; допускаются разные файлы. Без блока — прежние нулевые начальные поля. Сетка и конечность проверяются, ψ должна удовлетворять нулевым стенкам, границы ω пересчитываются по Тому из выбранной ψ. Физика и управление остаются из текущего YAML. Новый отсчёт времени начинается с нуля, `n_time_steps` — новые шаги. В API: `warm_up()` → `load_initial_state()` → шаги. `run.py`, `--check`, `--benchmark` вызывают загрузку сами.

Resume не дописывает старые результаты: обычное правило замены `binaries/` сохраняется. Входы загружаются до замены, затем копируются в `resume.psi.input.bin`, `resume.omega.input.bin`; происхождение, SHA256 и времена исходных полей — в `summary.json: initial_state`. Для сохранения предыдущей истории используйте другой конфиг. Нельзя молча трактовать исходное время как время нового запуска или автоматически переносить старую конфигурацию.

Общий выбор эксперимента и явный интерпретатор находятся в `solver_python_run/settings.sh`. По умолчанию это `pulsation_re260` и `../.venv/bin/python` относительно `alex`. Не добавляйте bash-fallback, `pipefail` или альтернативные пути запуска без необходимости.

Команды из `alex/`:

| Команда | Назначение |
|---|---|
| `bash solver_python_run/check.sh` | Проверить конфиг и вычислить источник без расчёта течения |
| `bash solver_python_run/run.sh` | Выполнить расчёт выбранного эксперимента |
| `bash solver_python_run/render.sh` | Построить кадры и график невязок |
| `bash solver_python_run/video.sh` | Построить кадры и видео ψ, ω, линий тока |
| `bash solver_python_run/stability.sh` | Найти приближение, стационар Ньютона и спектр |
| `bash solver_python_run/compare.sh` | Сравнить базовый и управляемый расчёты |
| `bash solver_python_run/run_projection.sh` | Полное вычитание парной проекции после каждого шага |
| `bash solver_python_run/run_rhs.sh` | Парная поправка в обеих правых частях |
| `bash solver_python_run/projection_comparison.sh` | Сопоставить три расчёта по снимкам и невязкам |
| `bash solver_python_run/distance.sh` | Построить расстояние до стационара по сохранённым снимкам |
| `bash solver_python_run/plot_forcing.sh` | Предварительно показать магнитное поле и источник |
| `bash solver_python_run/verify_magnets.sh` | Проверить поле, производные и короткий магнитный расчёт |
| `bash solver_python_run/test.sh` | Запустить pytest с изолированными результатами |
| `bash solver_python_run/benchmark.sh` | Измерить скорость после прогрева Numba |

`compare.sh` и `distance.sh` явно выбирают пару базового/управляемого экспериментов внутри скриптов; магнитные инструменты выбирают магнитный YAML. Они не целиком следуют выбору в `settings.sh`.

Зависимости перечислены в `solver_python/requirements.txt`. Сборка активного CPU-решателя не нужна: Numba компилирует ядра при запуске. Сравнение с архивным C++ требует компилятор и Eigen из репозитория.

## Карта результатов

Подпапки создаются соответствующим этапом; отсутствие ещё не рассчитанного этапа нормально.

| Папка внутри `results/<name>/` | Содержимое и смысл |
|---|---|
| `binaries/` | Основной расчёт: `result_<step>.bin`, `residual_history.csv`, `summary.json`, копии входного/разрешённого YAML, `forcing.npz`; для custom — копия исходника источника, для управления — `control_history.csv` |
| `figures/` | Графики невязок, поля/источника, расстояния до стационара и управления; также численные отчёты `forcing_preview.json`, `comparison.json` |
| `figures/frames/` | PNG каждого сохранённого снимка: ψ, ω, линии тока; исходные кадры для видео |
| `videos/` | `psi.mp4`, `omega.mp4`, `streamplot.mp4` |
| `tables/` | Производные таблицы анализа, например `distance_to_equilibrium.csv` |
| `stationary/` | Кандидат для Ньютона по минимуму изменения соседних снимков: `stationary_state.bin`, таблица/график разностей и линии тока. Сам кандидат ещё не доказанный стационар |
| `newton/` | Уточнённый стационар `equilibrium.bin` и история итераций `newton_history.csv` |
| `linear_stability/` | Собственные значения, спектр с/без управления, `report.json`, пакет стационара и базиса `stabilization.npz` |
| `verification/<дата>/` | Отдельный проверочный магнитный запуск со снимками и `verification.json`; появляется после `verify_magnets.sh` |

Снимки имеют формат `ALEXBIN1`, поля `(nx, ny)` в порядке x, y: ψ, ω, u, v и заголовок с параметрами/временем. Используйте `snapshot_io.py`, не пишите второй несовместимый читатель. `result_0.bin` содержит состояние после первого шага, с временем `dt`; последнее состояние сохраняется независимо от частоты записи.

CSV невязок и управления записываются при сохранении или логировании, а не обязательно на каждом шаге. `control_history.csv`: `max_control` относится к ω, `max_control_psi` добавляется для парного управления. Для RHS это скорость коррекции до умножения на dt, для projection — полная вычитаемая поправка; единицы записаны в `summary.json`. Пакет управления копируется в `binaries/stabilization.input.npz`, SHA256 — в summary. Расстояния в `distance_history.py` — относительные евклидовы нормы по полной сетке, отдельно для ψ и ω, по сохранённым снимкам.

Повторный запуск заменяет только распознанную папку `binaries/` данного эксперимента. Остальные результаты не очищаются: после изменения параметров пересоздайте зависимые графики, видео, стационар и моды. Копии конфигов в результатах — записи о запуске; рабочие YAML находятся в `configs/`. Старые перенесённые отчёты могут содержать исторические абсолютные пути.

## Обязательные численные соглашения

Всегда используйте Аракаву и существующую факторизованную схему с прогонками. Порядок шага: ψ → границы Тома → ω → невязки. Сохраните смешанные поправки факторизации и согласованные граничные значения промежуточной прогонки.

Соглашения: `u=ψ_y`, `v=−ψ_x`, `ω=−Δψ`, `J=ψ_x·ω_y−ψ_y·ω_x`; правая часть содержит `+J_A+S`. ψ обновляется релаксацией, поэтому время — **псевдовремя**. Не интерпретируйте динамику как физическую без отдельного обоснования.

Используйте float64. Ускорять разрешено программную реализацию при сохранении задачи и алгоритма. Не уменьшайте сетку, не меняйте dt, точность, критерий остановки или частоту проверки невязок ради скорости. Не включайте `fastmath`. Потоки задаются `execution.threads`; сейчас параллельны только независимые линии прогонок.

Источник имеет тип `none`, `custom` или `magnets`, без фамилий в именах. Custom-функция `source(x,y,lx,ly)` возвращает готовый безразмерный источник завихренности. Магниты задаются списком `[x, y, d, B]` в СИ: d — от точки диполя до дна, B — осевое поле отдельного диполя в плоскости модели. Поля суммируются. Ток задаётся плотностью в А/м². Модельные координаты и амплитуды нельзя выдавать за данные статьи.

## Стабилизация и текущие эксперименты

- `pulsation_re260` — базовый гармонический расчёт без управления.
- `pulsation_re260_stabilized` — та же задача с поправкой в правой части.
- `magnets_2x3_re260` — собственная установка из шести диполей.
- `pulsation_re260_base` — базовый расчёт для нового сравнения; существующий миллионный прогон переиспользован после побитовой проверки первых 1001 шагов.
- `pulsation_re260_projection` — полное вычитание парной проекции после каждого шага, затем пересчёт границ Тома.
- `pulsation_re260_rhs` — поправка в обеих правых частях, gain=1.
- `pulsation_re260_{base,projection,rhs}_t30` — продолжения соответствующих вариантов из τ=10 на 2000000 новых шагов до общей τ=30. В бинарниках время локальное 0–20; для общей шкалы анализа требуется явный `--time-offset 10` в `compare_projection.py`. Начальные поля загружены через YAML `resume`; старые прогоны сохранены отдельно.

Старые YAML без `method`/`components` сохраняют управление `−gain·P(ω−ω*)` только в RHS ω (`method: rhs`, `components: omega`). Базис хранится строками B на внутренних узлах ω, `P=B.T@B`, нормировка евклидова. Множитель dt применяется ровно один раз.

Пользователь подтвердил коррекцию **обеих компонент** для нового сравнения (`components: state`). В `projection.py` строится парный базис `(φ,η)` с `Δ_h φ+η=0`, ортонормированный в невзвешенной евклидовой метрике объединённых внутренних узлов `(ψ,ω)`. `state_basis` хранится в пакете. Одна система коэффициентов используется для обеих компонент; поправка считается от отклонения от `(ψ*,ω*)`. Метрику нельзя молча менять на две независимые проекции или относительные нормы.

`method: projection`: выполнить обычный шаг, вычесть полную парную проекцию, обновить границы Тома, вычислить исходные невязки; исправленная пара идёт в следующий шаг. Требуется gain=1, множителя dt нет. `method: rhs`: один раз вычислить проекцию старой пары и вычесть `dt*gain` каждой компоненты в соответствующем RHS до прогонок. На стационаре управление исчезает. Невязки обоих методов — исходные уравнения без управления. Базовый алгоритм и Аракава не меняются.

Для `method: rhs` разрешён конечный отрицательный gain: при −1 получаем
**прибавление** dt*P(z−z*) к правым частям. Ограничение gain=1 для полной
post-step projection остаётся. Тест `pulsation_re260_rhs_t30_test` по уточнению
пользователя повторяет начальные условия и длительность `pulsation_re260_rhs`:
нулевые ψ,ω, без resume, 1000000 шагов до τ=10, отличается только gain=−1.
Не трактовать t30 в его имени как длительность. Ошибочно начатое продолжение
из τ=10 остановлено; его лог/метаданные в `legacy/maintenance/cancelled_rhs_addition_resume/`.

Файл стабилизации должен соответствовать сетке, Re, источнику и стенкам. Новые пакеты сохраняют метаданные источника/границ; старые проверяются по невязке сохранённого стационара. Не обходите эти проверки.

`stability.py` исключает ψ через Пуассон. Его спектр нельзя автоматически считать спектром полного псевдовременного солвера или матрицы одного шага. Сохранение красивой картинки не доказывает сходимость: проверяйте расстояние, невязки и `summary.json: converged`.

Полное вычитание и RHS с gain=1 имеют разную силу воздействия: сравнение не изолирует только порядок операций. `compare_projection.py` сохраняет таблицы `tables/state_projection_history.csv` в каждом эксперименте и общие графики/JSON `figures/projection_*` у базового. Коэффициенты диагностируются по сохранённым снимкам. Архивное вычитание из готовых снимков не возвращает исправленное состояние в солвер и не заменяет этот эксперимент. Спектр `A−gain*Pω`, экспортируемый `stability.py`, относится к старому управлению по ω и не является спектром нового парного управления.

Первое сравнение выполнено до τ=10 (миллион шагов): оба новых расчёта завершены, но допуск невязки 1e-10 не достигнут. Числа и происхождение базы — `results/pulsation_re260_base/figures/projection_comparison.json`. Проверки реализации: 58 pytest; рабочая сетка, сохранение стационара и пробные 10000 шагов — `legacy/maintenance/state_control_checks.json`. Эти результаты относятся к зафиксированным YAML и базису; не распространяйте выводы на другой gain или метрику проекции.

Продолжения `_t30` завершены: 2000000 новых шагов каждого варианта, общая τ=30. Относительные расстояния (ψ,ω): база (0.523,0.453), вычитание (5.78e-12,5.84e-12), RHS (6.84e-11,5.53e-11). Позднего ухода управляемых решений на этом интервале не наблюдалось; `converged=false`, поскольку Rω≈1.30e-9 и 2.49e-9 выше допуска 1e-10. Вычитание вышло на численное плато, RHS продолжал приближаться. Общий график 0–30 и подробный отчёт — `results/pulsation_re260_base_t30/figures/projection_comparison_0_30.png`, `continuation_analysis.json`; полные таблицы — `tables/full_state_projection_history.csv` у каждого продолжения. Нельзя выдавать близость полей за выполнение строгого критерия невязки или доказательство устойчивости на бесконечном интервале.

Для трёх `_t30` построены ψ/ω/streamplot-видео продолжений: 2001 кадр, 20 fps, τ=10.00001…30 в подписях. Общие цветовые шкалы всех трёх случаев — `results/pulsation_re260_base_t30/figures/video_shared_scale.json`; применённые шкалы — `figures/render_scale.json` каждого случая. `render.py` поддерживает `--time-offset`, `--workers`, `--scale-file`; численные параметры солвера они не меняют. Крестики показывают глобальные внутренние экстремумы ψ. Не называйте линии тока траекториями частиц. Видео почти стационарных полей не заменяют графики расстояний/невязок.

## Стиль, тесты и изменения

Новый опыт `pulsation_re260_rhs_corner_magnets_t15`: 1500000 шагов от нуля
до τ=15, gain=-1 для обеих компонент, плюс четыре постоянных диполя около
углов. Это опыт подпитки новых малых угловых вихрей, не восстановления
исходной четырёхвихревой структуры и не обещание бесконечного разгона.
`magnetic_actuation` — отдельный источник управления только в RHS ω;
обязательное `reference: base_forcing` сохраняет явную опорную задачу мод.
Сетка, Re, основной источник и стенки пакета по-прежнему строго проверяются.
`source`/`forcing.npz`, невязки и `converged` относятся к базовой задаче;
`forced_source` включает магнитную добавку, записанную отдельно в
`magnetic_actuation.npz` с SHA256 в summary. Базовый стационар не объявляется
стационаром дополненной задачи. Разрешены только fixed-duration режимы.
Воздействие постоянно с первого шага; обратной связи по угловым вихрям нет.
`corner_vortices.py` диагностирует положительные эллиптические максимумы ψ
в угловых окнах (20% длины, 25% высоты), ядро — связная область выше половины
максимума. Это не поиск сепаратрис; отсутствие пика/локального ядра в окне
не доказывает исчезновение вихря. С прежним тестом сравнивать только до τ=10.
Этот опыт завершён до τ=15: четыре угловых ядра сохранены. При τ≈10 максимумы
ψ слабой диагональной пары выше варианта без магнитов в 7.46 раза, другой —
в 1.48 раза. Между τ≈12 и 15 слабая пара ослабла на 7.03%, другая выросла на
10.74%: бесконечный/монотонный разгон всех четырёх не получен. Базовые невязки
Rψ≈0.11138, Rω≈17.8451, converged=false. Проверки: 84 pytest и побитовое
воспроизведение первых 1001 шаг прежнего gain=-1 без магнитной добавки.

`pulsation_re260_rhs_corner_magnets_j5_t15` повторяет этот опыт от нуля до τ=15
с единственным изменением: постоянный j_y=5 вместо 0.5 А/м², с первого шага.
Завершён. Четыре угловых ядра усилены, большой центральный вихрь сохранился.
При τ=15 максимумы ψ двух диагональных пар выше прежних в 23.60 и 2.91 раза;
максимумы скорости внутри диагностических ядер — в 9.56 и 1.75 раза.
На τ≈12…15 максимумы ψ изменились лишь на +0.50% и −0.77%: распад центрального
вихря и неограниченный разгон не получены. Невязки базы Rψ≈0.11235,
Rω≈112.9204, converged=false; нельзя трактовать их как дефект полной системы.
В графиках `corner_vortices.py` подписи сравнения теперь берутся из конфигов,
а не предполагают обязательно вариант без магнитов до τ=10.

Прототип геометрического подбора конечных магнитов: `magnet_design.py`, модель поля
`finite_magnets.py`, запуск `solver_python_run/design_magnets.sh`. Отдельная схема
YAML в `configs/magnet_placement_two/` не предназначена для `run.py`. Папка результатов
снова определяется именем YAML. Сохранённые координаты и размеры — `placement.yaml`,
рисунки — `figures/magnet_layout.png`, `mode_fit.png`, `magnet_responses.png`;
ошибки и ограничения — `report.json`, матрицы — `design.npz`.
Используются конечные однородно намагниченные параллелепипеды, аналитическое поле
и производные. Зазор здесь от верхней грани до внешнего дна; до плоскости расчёта
прибавляются толщина дна и высота над внутренним дном. Это не прежнее d диполя.
Подбираются координаты при фиксированных размерах, а не число магнитов. Цель —
omega-компоненты текущего `state_basis`; критерий — худшая относительная ошибка
пространственного приближения их комбинаций на всех внутренних узлах. Независимые
знакопеременные амплитуды идеализированы; постоянные магниты с одним общим током
их не обеспечивают. Не называть пространственное перекрытие управляемостью или
доказательством устойчивости. Runtime, Аракава и парное управление не изменены.
Первый подбор двух магнитов 10×10×5 мм дал около 99.3% ошибки формы; это не
доказательство невозможности стабилизации двумя локальными воздействиями.

`design_magnets.sh` теперь выбирает `configs/magnet_placement_array/`:
вложенный подбор 2–192 магнитов из 231 непересекающегося места. Монтажная рамка
явно расширена на 12 мм относительно кюветы; зелёный контур на рисунках — кювета.
Метод `greedy_dictionary` использует полную сетку для скалярных произведений,
а каждый отчётный МНК перепроверяется через SVD. Это поиск на заданных местах,
не доказанный глобальный оптимум непрерывных координат. При `control` амплитуды
ограничиваются регуляризацией Тихонова так, чтобы gain*R*||C_i||₂ ≤ limit,
где R — максимальная modal_norm из указанной таблицы. Не заявлять оптимальность
ограниченного МНК или аппаратную реализуемость. Ошибка для 192 магнитов 45.24%,
для всего словаря 44.69%. `count_comparison.csv` и `figures/count_comparison.png`
сопоставляют числа магнитов; `magnet_amplitudes.png` показывает матрицу C.
Координаты, все отклики и ограниченные коэффициенты сохранены; индивидуальная
картинка откликов показывает первые 4 магнита, чтобы не создавать гигантский PNG.
